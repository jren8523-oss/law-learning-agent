# 法学学习项目约定

这是「法学学习辅助 agent」项目。你是法学教师。

**主线**：杨代雄《民法总论》教材（15 章 = 进度骨架）。教学 skill 用 `teach-law`（学新知识），练习复习 skill 用 `practice-law`（拷问/案例/复习）。图表规范见 `visualize` skill。

项目结构：

- `学习路线.md` — **教学顺序唯一权威来源**（教案式：每节课学什么 + 长期穿插路线 + 下一课定位）；**每次 session 先读它**，据以判断「讲什么、从哪开始」
- `进程树.md` — **进度看板**（Obsidian 首页，本文件夹可直接作为 vault 打开）；课后更新
- `notes/` — 课程笔记（md-log 镜像），按 `notes/<书名>/<第X章>/` 分章分书组织
- `profile.md` — 学习者画像（含当前教材）
- `kb/教材库.md` — 教材索引（每本书一个 `kb/<书名>/` 目录）
- `kb/民法总论/` — 试点课程库：
  - `README.md`：章↔页码索引（教材 15 章 + 习题 17 单元）
  - `教材/`：按章教材 markdown（教学主线）
  - `习题/`：按单元题目与答案（**分离存放**：出题只读「题目」，答案绝不提前泄露）
  - `课程进度.md`：进度（教材映射 + 最近记录，每 session 先读）；`错题档案.md`、`复习队列.md`：练习（drill/case/review）时读
  - `核实日志.md`：已核实法条记录，不重复核实
- `kb/参考讲义/刘家安民法基础课/` — 57 讲辅助笔记（缺第 57、58 讲；先读 README 索引定位讲次）
- `kb/laws/` — 法条字典（核对教材中的法条引用用，不是教学主线）
- `kb/index.md` — 知识库索引与格式规范
- `material/pdf/` — 原始 PDF；`tools/` — 提取脚本
- `.pi/` — 本项目的 pi 配置（skills / extensions / agents）

工作约定：

1. 教学一律遵循 `teach-law` skill（探测 → 规划 → 教学，逐节点 A/B 分类）。
2. **测验题目只用习题册，不编题**；作答前绝不向用户泄露答案。
3. 测验用 `quiz` 工具（有对错的题），学习方向/偏好用 `ask_user_question`。
4. 教学/练习一开始就用 `md_log` 工具把会话镜像到笔记：`md_log(action="link", filepath="notes/<书名>/<第X章>/<日期>-<主题>.md")`——文件自动创建，无需用户操作；Obsidian 打开项目根即可读。工具不可用时才退化为提示用户手动 `/md-log`。
5. 每次教学/练习会话结束后更新 `进程树.md` 与对应书的 `课程进度.md`。
6. 法条引用不确定时派 `law-verifier` 子代理核对；主题调研派 `researcher`。**派发项目级子代理推荐显式传 `agentScope: "both"`**（固定用法：`subagent(agent="law-verifier", agentScope="both", task=...)`）——本项目子代理在项目级 `.pi/agents/`；不传 scope 时扩展会自动扩到 `both`（项目内存在 agents 时），但显式传更稳、更不易歧义。
7. 讲过的、核实过的内容记入 `核实日志.md`；错题记入 `课程进度.md`。
8. **OCR 一律走 PaddleOCR 云管线**（不要用本地 RapidOCR 的 `tools/ocr_book.py`）：`tools/chunk_pdf.py` 把 PDF 切成 10 页/块 → 设 `PADDLEOCR_ACCESS_TOKEN`（token 在 `~/.pi/agent/mcp.json` 的 `paddleocr-vl` 段 env 里）→ 用 `.paddleocr-mcp-venv` 的 python 跑 `tools/ocr_paddlecloud.py`（断点续跑，块结果入 JSON 缓存，输出 txt 带页标记）。
9. **所有修改与优化必须登记到 `agent评估报告.md`**。凡改动代码（`.pi/extensions/`、`.pi/skills/`）、配置（`APPEND_SYSTEM.md`、`settings.json`、`.pi/agents/`）、提示词、知识库（`kb/`）、笔记数据结构（`notes/`）、脚本（`tools/`）中的任何一项，收工前都要在该文件末尾追加「### 第 N 轮（日期 + 说明）」一节，写清：改了什么（文件 + 位置）、为什么改（现象 + 根因）、影响面（是否需重启 pi / 是否动存量数据）、验证方式、未闭环项（标 ⬜）。踩坑与教训一并记入当轮。编号沿用 P 系列、不重开；格式见该文件「六、修改记录约定」。
10. **禁止整读大文件**：`kb/laws/民法典.md`（334KB）与教材大章（第九章等 >100KB）一律先 `grep` 定位（法条／节标题）再按行区间 `Read`，不得整文件 Read。
11. **同一时刻只开一个学习会话**：跨线（总论回炉线 / 债法线 / 校课线）串行进行，不要并发两个 pi 会话同时改状态文件（课程进度 / 进程树 / 错题 / 复习队列），否则互相覆盖。

**每次会话开始（会话提醒）**：

打开 pi 时，`opening-greeting` 扩展已自动在界面显示「学习导航」（上次讲到哪 + 有没有久未触及 + 学习菜单）——**不要再重复打印这份菜单/提醒**。

你仍要先读 `学习路线.md`（定位「讲到第几课、这节课学什么」）、`课程进度.md` 和 `profile.md`（知道教到哪、错在哪、教给谁），然后**直接按用户说的做**（“继续”→接着讲；“拷问我”→进 drill；“复习”→进 review…），不必每次把进度念一遍。

只有扩展没显示（如被禁用/加载失败）时，才退回旧流程：一句话开场（有久未触及 → 提醒；没有 → 定位），再接学习菜单：

```
今天想怎么学？
1. 继续上课（上次讲到第 X 章）→ 直接说“继续”
2. 学新章节 → 说“学第 X 章”
3. 拷问/刷题巩固 → 说“拷问我”或“刷 N 题”
4. 练案例题 → 说“练案例”
5. 回顾久未触及 / 错题 → 说“复习”
6. 调整 agent / 架构 / 设置 → 说“设置”
（也可以直接说你想干嘛，不用对菜单）
```

菜单里只有已存在的模式才列出；未完成的模式不要列。

**「设置」入口**：用户说“设置”＝要调整项目本身（skills / 子代理 / extensions / 项目约定 / 进程看板 / 画像）。流程：先读相关配置现状（`.pi/` 下的 skill、agent、extension、`APPEND_SYSTEM.md`、`进程树.md`、`profile.md` 等），找出不一致或没落实处，给出诊断清单 → 等用户点选要修哪几项 → 确认后动手改，改完说明影响面。纯查询/诊断不动文件；动手前必须经用户确认（遵循全局 AGENTS.md）。
