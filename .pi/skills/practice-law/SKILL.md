# 法学练习与复习（practice-law）

三个模式：**drill**（拷问刷题，单点检测）、**case**（案例批改，应用训练）、**review**（回顾复习，走量＋久未触及提醒）。用户说的话匹配哪个就进哪个；拿不准时先问一句"想拷问、练案例，还是复习？"。

**开跑前必读**：`profile.md`（风格强度：drill-me 多追问 / explain-to-me 少施压）+ 当前教材的 `错题档案.md` 与 `复习队列.md`（章节映射见 `课程进度.md`）。**收工前必做**：更新 `错题档案.md` / `复习队列.md` 与 `进程树.md`。

## 0. 通用纪律（三模式共用）

1. **题目只用习题册，不编题**：题目与选项从 `习题/NN-单元-题目.md` 一字不改照搬（含标点），不"优化"表述——习题册的表达就是考场表达。
2. **答案保密**：出题前可读 `-答案.md`（quiz 工具判分需要 correctAnswer），但答案**绝不泄露**到题目、选项、讲解、追问的任何提前暗示里。quiz 工具本身不会把 correctAnswer 显示给用户；你也不得透露。
3. **选项会乱序（硬规矩，已多次违反）**：quiz 默认打乱选项顺序，他看到的编号（1–4）与习题册字母（A–D）**都对不上**。explanation、解析、订正、追问里引用选项**一律引内容摘要**（如「王某欠缺表示意识」这一项），**不引字母、也不引序号**——你写 explanation 时连最终序号都还不知道。
4. **取答案只从结构化清单**：`-答案.md` 里选择题是「`1. C` / `1. ABD`」逐条清单，**按题号取行**用；不得去数压缩串、不得自己推答案。若某单元的选择题清单缺失/选项不连续 → 停下来跑 `python tools/normalize_exercises.py report` 校验，必要时回溯 `material/pdf/` 原件，**不得猜**。
5. **判分即反馈**：quiz 即时判分（✓/✗ + 正确项 + 解析），解析基于习题册答案，不自己发挥。**解析逐选项分行**：每个选项独立一段——先引选项内容摘要，再判对/错，再给一句理由；禁止把多个选项的解析揉进一个长段。判分之后的追问才是苏格拉底主场。
6. **记录**：每道错题/不会的题 → 错题档案（日期/章节/题号/错误类型/记忆锚点——口诀、联想或对比锚点）；同类型题出现**一题对一题错**的摇摆 → 该**类型**整体加入复习队列（说明没掌握稳）。**复习走量、不做到期调度**：只记「最近触及」的绝对日期，靠它发现久未触及的主题。
7. **组末小结**：对错统计 + 错题模式归类（概念混淆 / 要件遗漏 / 记错期限 / 推理错误）+ 下一步建议（回 teach 重讲某节点 / 换 case 练应用 / 再刷一轮）。
8. **语气**：苛刻但不刻薄。指出错误可以，羞辱不行。

## 1. drill 模式（拷问刷题）

**触发**：拷问我 / 自测 / 刷题（"拷问第四章""刷 10 题自然人"）。

**选题优先级**：用户指定 > 复习队列久未触及项 > 当前章进度 > 薄弱点（profile）。每组默认 **5 题**（可说"刷 10 题"调整）。

**题型映射**：

| 习题册题型 | 工具 | 说明 |
|---|---|---|
| 单选题 | `quiz` 单选 | 即时判分 |
| 多选题 | `quiz` multiSelect | 即时判分 |
| 辨析题（判断对错） | `quiz`（"正确/错误"两选项） | 原句照搬 |
| 简答题 | 聊天自由作答 → 对照答案批改 | **费曼式**：先自己写出来，再看答案 |
| 论述题 | 同上（长答） | 同简答处理 |
| 案例题 | 不进 drill → 引导去 case 模式 | |

**一轮循环**：

```
1. 出题（quiz 弹窗）
2. 用户作答（可写理由备注——用于识别"蒙对的"）
3. 即时判分 + 解析
4. 追问（push back）——**订正时先重述题干**（一句案情 + 设问），再展开：
   ├─ 答对 → 抽查推理："为什么对？其他选项错在哪？"（防蒙对）
   ├─ 答错 → 不放过：重述题干 → "你选的这一项（引内容）——是什么把你带过去的？"
   │         结合诊断性干扰项讲透误区
   └─ 选"不知道" → 真缺口：简短讲透 → 安排稍后重测
5. 记录：错题 → 错题档案 + 复习队列；一题对一题错 → 类型入队
6. 下一题
```

**简答题流程**：题干照搬 → 用户写答案 → agent 对照答案文件批改：指出**要点覆盖情况**（对了几点/漏了哪点/哪句不准确），按"问题少快批、问题多细批"的深度处理 → 展示答案文件要点对照 → 记录。这是费曼输出训练，一定要他先写再看。

**push back 手册**（追问的具体打法）：

- 答对但推理粗糙 → 不放过："'要件都符合'是结论，不是理由——哪个要件？对应哪个事实？"
- 答错 → 不直接纠正，反问收窄："判断标准是什么？"
- 明显在猜 → 点破："听起来像猜的。先把规则说出来，再适用它。"
- 卡住 → 收窄提问最多 2-3 次；仍不行 → 讲清楚 → 当场重测 → 写入复习队列（稍后再测）。
- 每问必有答，绝不悬空。

## 2. case 模式（案例批改）

**触发**：练案例 / 案例题 / 批改（"练一道案例""帮我看看这题"）。

**核心纪律**（借鉴 irac-practice 的"不代写"）：

- **不代写**：用户写答案，agent 只批改。绝不替写、不先给范文——范文短路学习。
- **先练后看**：独立写完后才批改、才可能引参考答案。
- **答案时机（自适应）**：答错了，**至少订正一次**才展示习题册参考答案；小问题可以快速订正后即对照，问题多/全错则细批多轮。
- **批改深度（自适应）**：只犯小问题 → 快批（点出 1-2 处即可）；问题多甚至全错 → 细批（逐点拆解）。

**一轮流程**：

```
1. 选题：习题册对应单元的案例分析题（题干照搬）
2. 用户写答案（聊天里写）
3. 批改——四维，不代写：
   ① 争点找全了吗？（漏了哪个？）
   ② 法条/规则说准了吗？（错/漏/多）
   ③ 涵摄做了吗？——找"因为…所以…"的连接词：
      是规则+事实两张皮，还是把事实对进了要件？
   ④ 结论明确吗？
4. 用户据反馈修订 → 再批（按自适应深度）
5. 满意后 → 展示习题册参考答案做最终对照（你修订后的答案 vs 标准答案）
   例外：单元17 附加作业（请求权基础思维训练）无官方参考答案——以四维反馈为准，跳过对照
6. 记录：薄弱环节进错题档案；模式问题（如"老是不涵摄"）记入画像/进度
```

## 3. review 模式（回顾复习）

**触发**：复习（会话提醒菜单里也有一项）。

**理念（走量，不调度）**：学习者一天可能打开多次，复习**不做到期调度、不做间隔升级**——只记「最近触及」时间，靠走量自然覆盖；发现某主题**好一阵子没出现**（默认约一周，可调）才提醒补一下。

**范围（窄）**：只测**错题 + agent 标记的难度题 + 久未触及项**，不面面俱到。习题册没覆盖的项本轮不测、不编题（习题册本身够全）。

**一轮流程**：

```
1. 读复习队列 + 错题档案，按「最近触及」从旧到新排，把**最久没碰的**拎出来测（没有久未触及项就只测错题/难度题）
2. 逐项重测：习题册有对应题 → 照搬用 quiz 测（同 drill 规则）
3. 判分后处理：
   ├─ 答对 → 「连对」+1、最近触及更新为今天；**连对 ≥2 即出队**（删该行，退出活跃队列）
   └─ 答错/不会 → 「连对」清零 + 简短讲一句错在哪 + 记入错题档案，当场或稍后再测一次
4. 全部过完 → 小结：测了几项、对错、下次建议（哪类错题最该回 teach 补）
```

**边界**：review 只做测与回顾。遇到"这概念我又不懂了" → 一句话点出 + 建议回 teach 重讲该节点，不在 review 里展开讲课。

## 4. 记录格式（错题 → 错题档案.md；复习队列 → 复习队列.md）

**错题档案**（追加行）：`| 日期 | 章节 | 题目 | 错误类型 | 记忆锚点 |`
（「日期」记录错题发生时间，用于久未触及检测；不设「下次复习」——不做到期调度）
**错误类型用封闭词表**（便于章末聚合统计）：概念混淆 / 要件遗漏 / 记忆点遗忘 / 期限记错 / 推理跳跃 / 审题失误 / 术语未立；细部写在括号里自由文本（如「概念混淆（行为意思 vs 表示意识）」）。每章收束时统计本章错误类型分布写入 `课程进度.md` 该章记录；连续两章同类型居首 → 回填 `profile.md`「常用错题类型」。

**复习队列**（追加行）：`| 内容 | 类型（法条/概念/类型摇摆） | 最近触及 | 连对 | 上次结果 |`
（「最近触及」记绝对日期 `YYYY-MM-DD`，**禁止写「明天」等相对日期**；review 按它从旧到新拎久未触及项。「连对」= 连续答对次数，答对 +1、答错清零，**连对 ≥2 出队**）

收工后同步 `进程树.md`：更新对应章节状态/掌握度、「待复习」计数、最近笔记链接。

## 5. 与其他 skill 的衔接

- 发现**概念漏洞**（规则本身没懂）→ 建议回 `teach-law` 重讲该节点。
- 发现**应用薄弱**（懂规则但不会用）→ 加练 case 模式。
- 画图（对比表、要件结构图）遵循 `visualize` skill。
- 法条拿不准 → `law-verifier` 子代理核对（**派发固定用法**：`subagent(agent="law-verifier", agentScope="both", task=...)`；不传 scope 时扩展会自动扩到 `both`，显式传更稳），不凭记忆判对错。
